# PatchTool для начинающих

## Что это

PatchTool — приложение для Android, которое умеет **заглядывать внутрь файлов `.so`**
(это библиотеки с кодом, которые используют приложения и игры) и **менять в них байты**.

С его помощью можно:

- 🔍 узнать, что за библиотека (архитектура, размер, количество функций);
- 📋 получить список всех функций библиотеки с их адресами;
- ✏️ заменить кусочек кода на свой (патч);
- ↩️ вернуть всё как было, если что-то пошло не так.

Всё работает прямо на телефоне, компьютер не нужен.

> ⚠️ Меняйте только свои файлы или файлы, которые вам разрешено изменять.
> Правки чужих программ и игр могут нарушать их правила.

---

## Перед началом

1. **Дайте приложению доступ к файлам.**
   Настройки → Приложения → PatchTool → Разрешения → Файлы и мультимедиа →
   «Разрешить управление всеми файлами».
   Без этого приложение не сможет сохранять результаты.
2. **Знайте, где лежат результаты.** Всё, что создаёт приложение, попадает в папку
   `PatchTool_Files` в корне памяти телефона (`/storage/emulated/0/PatchTool_Files/`).
3. **Исходный файл не меняется.** Патч делается на копии, оригинал остаётся целым.

---

## Урок 1. Что внутри библиотеки

1. Откройте PatchTool и выберите файл `.so`.
2. Приложение само покажет архитектуру: `arm64`, `arm32`, `x86` или `x86_64`.
   (У большинства современных телефонов — `arm64`.)
3. Запросите **информацию о файле**. Вы увидите размер, контрольные суммы (MD5 и SHA256),
   число функций и число инструкций кода.

Строка `# of Instructions (.text)` показывает, сколько команд процессора в коде библиотеки.
Если вместо числа написано `N/A (Requires Capstone)`, это не ошибка: в этой сборке
просто нет модуля, который считает инструкции. На остальное это не влияет.

---

## Урок 2. Список функций (Dump)

Dump создаёт текстовый файл со списком функций библиотеки:

```
// RVA: 0x1a2b0  Size: 0x54
void _ZN7MyClass6updateEf();
```

Что здесь что:

- **RVA** — адрес функции внутри библиотеки;
- **Size** — сколько байт она занимает;
- строка ниже — имя функции (если оно «мангленное», над ним будет расшифровка).

Файл лежит в `PatchTool_Files` и называется `dumped_<имя библиотеки>.so.cpp`.
Открыть его можно любым текстовым редактором.

Если файл почти пустой, значит библиотека «очищена» (stripped): имён в ней почти нет.

---

## Урок 3. Первый патч

Патч — это замена нескольких байт по нужному адресу. Нужно знать три вещи:

1. **Offset** — место в файле, где начинается замена (в шестнадцатеричном виде, например `1A2B0`).
2. **Что записать** — байты (HEX) или команда на ассемблере (ASM).
3. **Архитектуру** библиотеки.

### Пример: заставить функцию всегда возвращать 1

Подходящие байты зависят от архитектуры:

| Архитектура | HEX | Ассемблер |
|---|---|---|
| arm64 | `20 00 80 D2 C0 03 5F D6` | `mov x0, #1; ret` |
| arm32 | `01 00 A0 E3 1E FF 2F E1` | `mov r0, #1; bx lr` |
| x86 / x86_64 | `B8 01 00 00 00 C3` | `mov eax, 1; ret` |

Порядок действий:

1. Выберите `.so`.
2. Введите **offset** начала функции.
3. Введите **HEX** (или **ASM**, если нужен ассемблер).
4. Запустите патч.
5. Готовый файл появится в `PatchTool_Files` под именем `<имя>_patched.so`.

Если заполнены и HEX, и ASM, используется ASM.

> Offset — это место в **файле**. Адрес RVA из дампа не всегда совпадает с ним.
> Если патч «не сработал», сначала проверьте это.

## Урок 4. Много патчей сразу (файл .ini)

Когда патчей много, удобнее записать их в текстовый файл с расширением `.ini`
и применить за один раз.

Создайте файл `patches.ini`:

```ini
# Всё после решётки — комментарий

[Patch_1]
offset=0x1A2B0
patch_hex=20 00 80 D2 C0 03 5F D6

[Patch_2]
offset=0x2000
patch_asm=mov x0, #1; ret
arch=arm64
```

Правила:

- каждый патч начинается с заголовка в квадратных скобках, имя может быть любым;
- `offset` обязателен;
- укажите либо `patch_hex`, либо `patch_asm`;
- если пишете `patch_asm`, обязательно добавьте `arch` (`arm64`, `arm32`, `x86` или `x86_64`).

Как применить:

1. Выберите `.so`.
2. В меню выберите **Import Patches (.ini)** и укажите свой файл.
3. Прочитайте лог: зелёные `[+]` — всё хорошо, красные `[-]` — этот патч пропущен.
4. Результат: `PatchTool_Files/<имя>_patched.so`.

Неудачный патч не ломает остальные: приложение пропустит его и применит все остальные.

---

## Урок 5. Как всё вернуть назад

Каждый раз при импорте `.ini` приложение создаёт файл-бэкап `<имя>.so.bak.ini`
с оригинальными байтами.

Чтобы откатить:

1. Выберите пропатченную `.so`.
2. В меню выберите **Restore from Backup** и укажите файл `.bak.ini`.
3. Получите `PatchTool_Files/<имя>_restored.so`.

Совет: не удаляйте `.bak.ini`, пока не убедитесь, что патч работает как нужно.

---

## Если что-то не получилось

| Что видите | Что делать |
|---|---|
| Папки `PatchTool_Files` нет | Выдайте разрешение «Доступ ко всем файлам» |
| `ASM is not available` | Эта сборка без модуля ассемблера. Пишите патч в HEX |
| `Invalid hex string provided.` | В HEX лишние символы или нечётное число цифр |
| `Skipping patch ...: Out of bounds` | Offset больше размера файла |
| `'patch_asm' needs an 'arch' key.` | В `.ini` забыли строку `arch=...` |
| Дамп почти пустой | Библиотека без имён функций (stripped) |
| Патч применился, но ничего не изменилось | Проверьте, что offset — смещение в файле, а не RVA из дампа |

## Словарик

- **ELF / .so** — формат файла библиотеки в Android и Linux.
- **Архитектура** — тип процессора: arm64, arm32, x86, x86_64.
- **Offset** — положение байта в файле.
- **RVA** — адрес функции при загрузке библиотеки в память.
- **HEX** — байты, записанные в шестнадцатеричном виде (`90 90 C3`).
- **ASM** — понятная человеку запись команд процессора (`mov x0, #1`).
- **Патч** — замена байт в файле.
- **Stripped** — библиотека, из которой удалили имена функций.
